CLOUD
วิธีตั้งค่าให้ข้อมูลอยู่รอดหลัง deploy (ใช้กับ Render ฟรี)
  1. สร้าง repo เปล่าบน GitHub (แนะนำ repo ส่วนตัว เช่น twentyfive-backup)
  2. สร้าง Token: Settings → Developer settings → Personal access tokens → classic (สิทธิ์ repo) หรือ fine-grained (สิทธิ์ Contents: Read and write)
  3. ตั้งตัวแปรแวดล้อมบน Render: BACKUP_KEY (รหัสลับเข้ารหัสอะไรก็ได้ เก็บไว้ให้ดี หาย = กู้ข้อมูลไม่ได้), BACKUP_GITHUB_TOKEN, BACKUP_REPO (รูปแบบ owner/repo)
  4. ระบบจะเข้ารหัสและ push ขึ้น branch data-backup ให้เองทุกครั้งที่มีการบันทึก (ไม่เกินทุก 30 วินาที)
  5. พอ deploy เสร็จ ดิสก์ Render ฟรีจะว่าง — ระบบจะ ดึงข้อมูลจาก GitHub → ถอดรหัส → เติมกลับให้เอง ตอนเปิดเซิร์ฟเวอร์

ส่งข้อมูลขึ้น Google ชีต

กำลังตรวจสอบ...

SHEET

วิธีตั้งค่าให้ส่งข้อมูลเข้า Google ชีตอัตโนมัติ (และกู้กลับได้)
  1. เปิด Google ชีตใหม่ 1 ไฟล์ → เมนู Extensions (ส่วนขยาย) → Apps Script
  2. วางโค้ดจากไฟล์ google-sheets/apps-script.gs แทนโค้ดเดิม แล้วตั้ง TOKEN เป็นรหัสลับของคุณ
  3. Deploy → New deployment → Web app · Execute as: Me · Who has access: Anyone แล้วคัดลอก URL ที่ลงท้าย /exec
  4. ตั้งตัวแปรแวดล้อม: SHEETS_WEBHOOK_URL = URL นั้น และ SHEETS_SECRET = รหัสเดียวกับ TOKEN
  5. จากนี้ชีต Applications (ใบสมัคร) และ Members (รายชื่อสมาชิก) จะถูกสร้างและอัปเดตให้เองทุกครั้งที่มีการบันทึก
  6. กู้คืน: ระบบเก็บสำเนาข้อมูลดิบไว้ในชีตลับ _raw ทุกครั้งที่ส่ง (อย่าลบชีตนี้) — ถ้าดิสก์เซิร์ฟเวอร์หาย ระบบจะดึงกลับให้เองตอนเปิดเซิร์ฟเวอร์ หรือกดปุ่ม กู้ข้อมูลจากชีตกลับมา ได้ทันที (โหลดเข้ามาต่อท้ายเลย ไม่เขียนทับของเดิม)

▲ ชีต Members มีคอลัมน์ชื่อผู้ใช้/รหัสผ่านบอร์ด — ควรตั้งชีตเป็น ส่วนตัว ไม่แชร์เป็นสาธารณะ
▲ แก้ข้อมูลในชีตด้วยมือไม่มีผลกับเว็บ (ระบบอัปเดตแถวตามรหัสทุกครั้ง แก้ที่ชีตอาจถูกแก้กลับ) — ให้แก้ที่หน้าแอดมินหรือบอร์ดแทน

บอทส่ง DM อัตโนมัติ

กำลังตรวจสอบ...

DM
วิธีตั้งค่าให้บอทส่งข้อความเองอัตโนมัติ
  1. สร้างแอปที่ discord.com/developers/applications → แท็บ Bot → คัดลอก Token แล้วตั้งเป็นตัวแปรแวดล้อม DISCORD_BOT_TOKEN
  2. เปิด SERVER MEMBERS INTENT ในแท็บ Bot (ถ้าอยากให้บอทค้นหา User ID จากชื่อผู้ใช้)
  3. เชิญบอทเข้าเซิร์ฟเวอร์ของคุณ (OAuth2 → scope bot) แล้วตั้ง DISCORD_GUILD_ID เป็นไอดีเซิร์ฟเวอร์
  4. ผู้สมัครต้องอยู่เซิร์ฟเวอร์เดียวกับบอท และเปิดรับ DM จากสมาชิกในเซิร์ฟเวอร์
  5. ทางที่ดีให้ผู้สมัครกรอก User ID (ตัวเลข 17-20 หลัก) ตอนสมัคร — บอทจะส่งได้แม่นที่สุด
