# TWENTYFIVE — Member Directory

เว็บไซต์รายชื่อสมาชิกโทนทอง-ดำ พร้อม intro animation, search/filter และหลังบ้านเพิ่ม/แก้ไข/ลบสมาชิก

## ต้องมี
- Node.js 18 ขึ้นไป
- VS Code

## รันในเครื่อง
1. แตก ZIP แล้วเปิดโฟลเดอร์ `TWENTYFIVE` ใน VS Code
2. เปิด Terminal > New Terminal
3. ติดตั้งแพ็กเกจ: `npm install`
4. ตั้งค่าตัวแปรแวดล้อมก่อนรัน

### Windows PowerShell
```powershell
$env:ADMIN_USER="admin"
$env:ADMIN_PASSWORD="ใส่รหัสผ่านที่คาดเดายากของคุณ"
$env:SESSION_SECRET="ใส่สตริงสุ่มยาวๆ ที่ไม่ซ้ำกับรหัสผ่าน"
npm start
```
5. เปิด http://localhost:3000
6. หลังบ้านอยู่ที่ http://localhost:3000/admin

ชื่อผู้ใช้เริ่มต้นคือ `admin` ส่วนรหัสผ่านคือค่าที่คุณกำหนดใน `ADMIN_PASSWORD` — ไม่มีรหัสผ่านตายตัวฝังไว้ในโค้ด

## ระบบสมัครเข้าแก๊ง + บอร์ดส่วนตัว
- `/apply` — หน้าสมัครเข้าแก๊ง กรอก ชื่อ IC, อายุ IC, ลิงก์เฟส IC, ดิสคอร์ด, ลิงก์ Google Drive และรายละเอียดแนะนำตัว พร้อมช่องตรวจสอบสถานะใบสมัคร
- `/admin` — กล่อง "ใบสมัครเข้าแก๊ง" ให้แอดมินคัดคน เลือกหมวดแล้วกด **รับเข้าแก๊ง** หรือกดไม่ผ่านพร้อมเหตุผล
- ตอนผู้สมัครกดส่งใบสมัคร ระบบจะ **ส่งข้อความตอบกลับอัตโนมัติ** ทาง DM (หรือให้แอดมินกด **แจ้งรับใบสมัคร** แล้วคัดลอกข้อความไปส่งเอง) เพื่อบอกให้รอผล — ระหว่างรอผลยังเข้ากลุ่มดิสคอร์ดไม่ได้
- แอดมินกด **ให้ออกจากแก๊ง** ที่แถวสมาชิกได้: ซ่อนจากหน้าเว็บ + ตัดสิทธิ์ล็อกอินบอร์ดทันที (ข้อมูลบอร์ดยังอยู่) แล้วดู/กู้กลับได้ที่แท็บ **ออกจากแก๊ง** ส่วนปุ่ม **ลบ** คือลบถาวรออกจากระบบ
- เมื่อกดรับเข้า ระบบจะออก `ชื่อผู้ใช้ (username)` + `รหัสผ่าน` ให้ แล้วพยายามส่งให้ผู้สมัครทาง **DM ดิสคอร์ด** อัตโนมัติ (ถ้าตั้งค่า bot ไว้) ถ้ายังไม่ได้ตั้งค่า จะโชว์ข้อความ DM พร้อมปุ่ม **คัดลอกข้อความ** ให้แอดมินส่งเอง
- `/board` — สมาชิกล็อกอินด้วย **ชื่อ IC + รหัสผ่าน** ที่ได้รับ แล้วตกแต่งบอร์ดของตัวเองได้ (ชื่อที่แสดง, แท็กไลน์, สถานะ, แนะนำตัว, รูปโปรไฟล์, โซเชียล, ธีมสี และลวดลาย) บอร์ดจะไปแสดงบนหน้าแรกของการ์ด/โปรไฟล์สมาชิก
- ระบบจำการล็อกอินด้วยคุกกี้/เซสชัน (เก็บใน `data/sessions.json`) จึงไม่ต้องล็อกอินซ้ำ และเปิดหน้า `/board` กลับมาจะดึงข้อมูลเดิมให้อัตโนมัติ

## ระบบเพลง (เพลงประจำบอร์ด + เพลงเปิดเว็บ)
- **เพลงประจำบอร์ด** — สมาชิกตั้งได้ 1 เพลงต่อบอร์ดที่ `/board` (ชื่อเพลง / ศิลปิน / ลิงก์) พร้อมดูตัวอย่างตัวเล่นแบบเรียลไทม์ที่การ์ดตัวอย่างด้านขวา เพลงจะโชว์บนการ์ดสมาชิกหน้าแรก (มีป้าย ♪) และฝังตัวเล่นในหน้าโปรไฟล์ (ปิดหน้าต่างโปรไฟล์ = หยุดเสียงทันที)
- ลิงก์ที่ฝังเล่นได้อัตโนมัติ: **YouTube / YouTube Music, Spotify, SoundCloud, Apple Music** — ลิงก์อื่น ๆ แสดงเป็นปุ่ม "เปิดเพลง ↗" ไปเปิดในแท็บใหม่แทน (ระบบแยกแยะเองจากลิงก์)
- แอดมินแก้เพลงของสมาชิกแต่ละคนได้จากฟอร์ม "เพิ่ม/แก้ไขสมาชิก" ในหลังบ้าน (ช่อง *เพลงประจำบอร์ด / ศิลปิน / ลิงก์เพลง*) หรือให้สมาชิกแก้เองที่ `/board` ก็ได้ — ทั้งสองฝั่งแก้คนละบอร์ดไม่ชนกัน
- **เพลงเปิดเว็บ** — แพนล์ **เพลงเปิดเว็บ** ในหลังบ้าน `/admin` ตั้งเพลงเดียวให้เล่นอัตโนมัติตอนผู้ชมเปิดเว็บทุกหน้า (`/`, `/apply`, `/board`) — **เสียงล้วน ไม่มีตัวเล่น/ปุ่ม/ป้าย ให้เห็นบนหน้าเว็บเลย** (ตัวเล่นถูกซ่อนไว้นอกจอ)
  - ใส่เพลงได้ 2 แบบ — **วางลิงก์** (YouTube / Spotify / SoundCloud / Apple Music) หรือ **อัปโหลดไฟล์เสียงจากเครื่อง** (mp3 / m4a / wav / ogg / opus / webm / flac ไม่เกิน 25 MB) ไฟล์จะถูกเก็บที่ `public/uploads/site-song.*` (เก็บเพลงไฟล์เดียวเสมอ อัปโหลดใหม่แทนที่ไฟล์เก่า) และเล่นด้วย `<audio>` ของเบราว์เซอร์โดยตรง
  - ติ๊ก **ซ่อนชื่อเพลง** ได้ในฟอร์มเดียวกัน — ตัวเล่นลอย (หน้าโปรไฟล์/หลังบ้าน) จะไม่โชว์ชื่อเพลง/ศิลปิน (ระบบจะเลือกซ่อนไว้ให้อัตโนมัติทุกครั้งที่อัปโหลดไฟล์) ส่วนหน้าเว็บไม่มีตัวเล่นให้เห็นอยู่แล้ว
  - ถ้าเบราว์เซอร์บล็อกการเล่นอัตโนมัติ (Chrome จะบล็อกเสียงที่ยังไม่มีการแตะหน้าจอ) ระบบจะเริ่มเล่นทันทีที่ผู้ชมคลิก/แตะหน้าจอครั้งแรก — ไม่ต้องกดซ้ำ
- API: `GET /api/site-song` (สาธารณะ), `PUT` / `DELETE /api/site-song` และ `POST /api/site-song/upload` (แอดมินเท่านั้น — รับไฟล์เสียงแบบ raw body) — เพลงประจำบอร์ดเก็บรวมกับข้อมูลสมาชิกใน `data/members.json` ส่วนเพลงเปิดเว็บเก็บที่ `data/settings.json` ทั้งคู่สำรอง seed / GitHub / Google ชีต ตามระบบเดิมอัตโนมัติ
- ไฟล์ที่เกี่ยวข้อง: `public/song.js` (แปลงลิงก์เป็นตัวเล่น + สไตล์), `public/music.js` (เล่นเพลงเปิดเว็บแบบซ่อน — ไม่มี UI ให้เห็น)

### ตัวแปรแวดล้อมเพิ่มเติม (ไม่บังคับ)
- `DISCORD_BOT_TOKEN` — โทเคนบอทดิสคอร์ด ถ้าใส่ ระบบจะส่ง DM อัตโนมัติ (ต้องมี User ID ของผู้สมัครเป็นตัวเลข 17-20 หลัก)
- `DISCORD_GUILD_ID` — ไอดีเซิร์ฟเวอร์ดิสคอร์ด ถ้าใส่ด้วย บอทจะค้นหา User ID จาก "ชื่อผู้ใช้" ให้อัตโนมัติ (ต้องเปิด SERVER MEMBERS INTENT และบอทต้องอยู่ในเซิร์ฟเวอร์นั้น)
- `PUBLIC_URL` — ลิงก์เว็บจริง เช่น `https://your-app.onrender.com` ใช้ใส่ในข้อความ DM
- `DISCORD_INVITE` — ลิงก์เชิญเข้ากลุ่มดิสคอร์ดของแก๊ง (ค่าเริ่มต้น `https://discord.gg/rZBmUgYtx2`) ใช้ในข้อความ DM ที่ส่งให้ผู้สมัคร และป้ายเชิญบนหน้า `/apply`
- `BACKUP_KEY` / `BACKUP_GITHUB_TOKEN` / `BACKUP_REPO` / `BACKUP_BRANCH` — ระบบสำรองข้อมูลขึ้น GitHub (ดูหัวข้อถัดไป)
- `SHEETS_WEBHOOK_URL` / `SHEETS_SECRET` / `SHEETS_INTERVAL` / `SHEETS_KEEPALIVE` — ระบบส่งข้อมูลขึ้น Google ชีต (ดูหัวข้อ "ส่งข้อมูลเข้า Google ชีต")

## ข้อมูลสำรองอัตโนมัติ
### 1) สำรองบนเครื่อง (seed) — ทำงานเสมอ
- ทุกครั้งที่บันทึก ระบบจะเขียนสำเนาลง `data/members.seed.json` และ `data/applications.seed.json` ให้อัตโนมัติ
- ถ้าไฟล์หลัก `data/members.json` / `data/applications.json` หายหรือเสียหาย ระบบจะ **กู้คืนจาก seed ให้เองอัตโนมัติ** ตอนอ่านข้อมูลครั้งถัดไป
- หน้าแอดมินมีปุ่ม **สำรองข้อมูลเดี๋ยวนี้** และแสดงเวลาสำรองล่าสุด/ประวัติการกู้คืน

### 2) สำรองขึ้น GitHub (เข้ารหัส) — สำหรับ Render ฟรี ที่ดิสก์ถูกล้างทุกครั้งที่ deploy/restart
> เว็บบน Render แพ็กเกจฟรีจะล้างดิสก์ทุกครั้งที่ deploy/restart ดังนั้น seed บนเครื่องอย่างเดียว **ไม่พอ** — ระบบจึงเข้ารหัสข้อมูล (AES-256-GCM) แล้วเก็บไว้บน GitHub แทน

**ตั้งค่าครั้งแรก**
1. สร้าง repo เปล่าบน GitHub (แนะนำ repo **ส่วนตัว** เช่น `yourname/twentyfive-backup`)
2. สร้าง Token: GitHub → Settings → Developer settings → Personal access tokens → classic (สิทธิ์ `repo`) หรือ fine-grained (สิทธิ์ Contents: **Read and write**)
3. ตั้งตัวแปรแวดล้อมบน Render:
   - `BACKUP_KEY` = รหัสลับอะไรก็ได้ที่เดายาก (ใช้เข้ารหัส) — **ห้ามหาย ถ้าหายกู้ข้อมูลไม่ได้** ควรเก็บไว้ที่ปลอดภัย
   - `BACKUP_GITHUB_TOKEN` = โทเคนที่สร้างจากข้อ 2
   - `BACKUP_REPO` = ชื่อ repo รูปแบบ `owner/repo` (หรือวางลิงก์ `https://github.com/owner/repo` ก็ได้)
   - `BACKUP_BRANCH` = branch สำหรับเก็บข้อมูล (ค่าเริ่มต้น `data-backup`)

**ทำงานยังไง**
- ทุกครั้งที่มีการบันทึกข้อมูล (อนุมัติใบสมัคร, ตกแต่งบอร์ด ฯลฯ) ระบบจะเข้ารหัสแล้ว push ขึ้น branch ที่ตั้งไว้ (ไม่ถี่กว่าทุก 30 วินาที) และตอนเซิร์ฟเวอร์จะปิด (Render ส่ง SIGTERM ก่อน deploy) จะเตะข้อมูลที่ค้างส่งให้หมดก่อน
- **ตอน deploy เสร็จ** ดิสก์จะว่าง → ระบบจะดึงไฟล์ `.seed.enc` จาก GitHub → ถอดรหัส → เติมข้อมูลกลับให้เอง พร้อมโชว์ประวัติในหน้าแอดมิน
- ไฟล์ที่ push ขึ้นเป็น `.enc` (เข้ารหัสแล้ว) บน GitHub ดูไม่ได้โดยไม่มี `BACKUP_KEY`
- แนะนำให้ใช้ **branch แยก** (`data-backup`) ไม่ใช้ branch เดียวกับที่ Render deploy เพื่อกัน deploy loop หรือใช้ repo แยกต่างหากไปเลยก็ได้
- **กู้มือ:** ดาวน์โหลด `members.seed.enc` / `applications.seed.enc` จาก GitHub ใส่ไว้ในโฟลเดอร์ `data/` แล้วเปิดเซิร์ฟเวอร์ (มี `BACKUP_KEY` อยู่) ระบบจะถอดรหัสและเติมข้อมูลให้เอง

## ส่งข้อมูลเข้า Google ชีต
> ทุกครั้งที่มีการบันทึก ระบบจะส่งข้อมูลไป **อัปเดตต่อ** ใน Google ชีตให้อัตโนมัติ (แถวเดิมแก้ในที่เดิม แถวใหม่ต่อท้าย ไม่ล้างชีต) — ได้ทั้งชีต **Applications** (ใบสมัครทุกคน), **Members** (รายชื่อสมาชิกทุกคน พร้อมชื่อผู้ใช้/รหัสผ่านบอร์ด), **Activity Reports**, **Score History**, **Leave History**, **Behavior History** และ **Leaderboard** (ตารางอันดับ snapshot ที่เขียนทับใหม่ทุกครั้งเพื่อให้ลำดับถูกต้อง) ใช้เป็นฐานข้อมูลสำรองที่เปิดดู/แชร์ได้ง่าย

**ตั้งค่าครั้งแรก (ทำครั้งเดียว ~3 นาที)**
1. เปิด Google ชีตใหม่ 1 ไฟล์ → เมนู **Extensions (ส่วนขยาย) → Apps Script**
2. ลบโค้ดเดิมทั้งหมด แล้ววางโค้ดจากไฟล์ [`google-sheets/apps-script.gs`](google-sheets/apps-script.gs) แทน และตั้งตัวแปร `TOKEN` ให้เป็นรหัสลับของคุณ
3. กด **Deploy → New deployment** → เลือกชนิด **Web app**
   - **Execute as:** `Me`
   - **Who has access:** `Anyone`
   แล้วกด Deploy → อนุญาตสิทธิ์ → คัดลอก **URL ที่ลงท้ายด้วย `/exec`**
   - **ถ้าเคย deploy เวอร์ชันเก่าไว้แล้ว** ให้ไปที่ **Deploy → Manage deployments → ไอคอนดินสอ → Version: New version → Deploy** เพื่อให้โค้ดใหม่ (หัวตาราง Activity Reports / Score History / Leave History / Behavior History / Leaderboard) มีผล
4. ตั้งตัวแปรแวดล้อมบนโฮสต์:
   - `SHEETS_WEBHOOK_URL` = URL ที่คัดลอกมา
   - `SHEETS_SECRET` = รหัสเดียวกับ `TOKEN` ในข้อ 2 (ถ้าไม่ตั้งค่านี้ ใครรู้ URL ก็ยิงข้อมูลเข้าชีตได้)
   - `SHEETS_INTERVAL` = ส่งไม่ถี่กว่าทุกกี่วินาที (ค่าเริ่มต้น `20`)
   - `SHEETS_KEEPALIVE` = ส่งข้อมูลขึ้นชีตอัตโนมัติทุกกี่วินาที แม้ไม่มีการแก้ไขอะไรเลย (ค่าเริ่มต้น `300` = 5 นาที, ตั้ง `0` = ปิด)
   - `SHEETS_TIMEOUT` = เวลารอ Google ชีตตอบเป็นกี่วินาที (ค่าเริ่มต้น `60`) — **สำคัญตอนกดกู้**: Apps Script ตื่นนอน (cold start) ครั้งแรกหลังเว้นช่วงช้าได้ 20-40 วินาที ถ้า timeout สั้นกว่านั้นจะขึ้น `This operation was aborted` ทั้งที่ชีตไม่ได้เป็นอะไร ระบบจะลองซ้ำให้ 1 ครั้งอัตโนมัติก่อนรายงานผิด

**ทำงานยังไง**
- ระบบส่งแบบ **อัปเดตต่อตามรหัส** (upsert) → เพิ่มสมาชิก = ต่อท้าย, แก้ = แก้แถวเดิม, ลบบนเว็บ = ลบแถวนั้นบนชีต ไม่มีแถวซ้ำ และไม่ล้างชีตทั้งหมดแล้วลงใหม่
- ชีต **Leaderboard** เป็นข้อยกเว้น: ใช้โหมด `replace` เขียนทับทั้งชีตทุกครั้ง เพราะเป็นตารางอันดับที่ต้องเรียงใหม่ทั้งตาราง
- ส่งอัตโนมัติหลังบันทึกทุกครั้ง (เว้นระยะขั้นต่ำตาม `SHEETS_INTERVAL`) และ**เตะคิวที่ค้างส่งตอนเซิร์ฟเวอร์ปิด** (SIGTERM) เหมือนระบบสำรอง GitHub
- **ส่งอัตโนมัติทุก `SHEETS_KEEPALIVE` วินาทีด้วย แม้ไม่มีใครแก้อะไร** → ทำให้ "มีสำเนาอยู่บนชีตเสมอ" หลังตั้งค่าเสร็จไม่กี่วินาที จึงกดปุ่ม **กู้ข้อมูลจากชีตกลับมา** ได้ทุกเมื่อ โดยไม่ต้องมากด "ส่งข้อมูลขึ้นชีตเดี๋ยวนี้" ก่อน
- **ระบบจะไม่ส่งข้อมูลตัวอย่างชั่วคราวขึ้นชีต/GitHub** — ถ้าเปิดเซิร์ฟเวอร์แล้วดิสก์ว่าง (เช่นเพิ่ง deploy) แล้วกู้ข้อมูลจากคลาวด์ยังไม่สำเร็จ ระบบจะถือข้อมูลชุดนั้นเป็น "ข้อมูลชั่วคราว" และ**ไม่แตะสำเนาจริง**ที่มีอยู่บนชีต/GitHub จนกว่าจะมีการบันทึกข้อมูลจริงครั้งแรก
- ถ้าส่งไม่สำเร็จ จะเก็บคิวไว้ลองใหม่รอบถัดไป (ไม่ยิงรัว) และโชว์สาเหตุในหน้าแอดมิน
- ตอนเปิดเซิร์ฟเวอร์ ระบบจะลองดึงสำเนาจาก Google ชีตซ้ำถึง **3 รอบ** (ห่างกัน 3 วินาที) เผื่อเน็ตสะดุดตอน cold start ของ Render
- หน้าแอดมิน (`/admin`) มีแถบ **ส่งข้อมูลขึ้น Google ชีต** บอกเวลาส่งล่าสุด/จำนวนแถว/ข้อผิดพลาด พร้อมปุ่ม **ส่งขึ้นชีตเดี๋ยวนี้**
- คอลัมน์ในชีตแก้ไม่ได้จากฝั่ง Google ชีต (ระบบอัปเดตแถวตามรหัสทุกครั้ง) — แก้ข้อมูลที่หน้าแอดมินหรือบอร์ดเท่านั้น
- **▲ ชีต Members มีรหัสผ่านบอร์ดอยู่ด้วย ควรตั้งชีตเป็นส่วนตัว (ไม่แชร์สาธารณะ)**

### กู้ข้อมูลกลับจาก Google ชีต → เว็บ
นอกจากตารางที่อ่านง่าย ระบบยังส่ง **สำเนาข้อมูลดิบ (JSON ครบทุกฟิลด์)** ไปเก็บในชีตลับชื่อ `_raw` ทุกครั้งที่ส่ง ดังนั้นกู้กลับได้ **ไม่สูญหาย** (ได้ทั้งรหัสผ่านบอร์ด ผลงานบอร์ด ธีม และรหัสประจำตัวเดิม)

กู้ได้ 2 ทาง
1. **อัตโนมัติ** — ตอนเปิดเซิร์ฟเวอร์ ถ้าดิสก์ว่าง (เช่นเพิ่ง deploy บน Render ฟรี) ระบบไล่กู้ตามลำดับ: ไฟล์บนเครื่อง → `*.seed.enc` บนเครื่อง → GitHub backup → **Google ชีต** เป็นทางสุดท้าย
2. **กดเอง** — หน้าแอดมิน แถบ *ส่งข้อมูลขึ้น Google ชีต* → ปุ่ม **กู้ข้อมูลจากชีตกลับมา** (โหลดเข้ามาทันที **รวมเพิ่ม** — รหัสที่มีบนเว็บอยู่แล้วไม่ถูกแตะ เฉพาะรายการที่หายไปจะถูกต่อท้าย)

ข้อควรรู้
- ต้อง **ส่งขึ้นชีตสำเร็จอย่างน้อย 1 ครั้ง** ก่อน จึงจะมีสำเนาให้กู้ (ถ้ายังไม่เคยส่ง ปุ่มจะแจ้งว่าไม่มีสำเนา)
- **ห้ามลบชีต `_raw`** — เป็นที่เก็บสำเนาสำหรับกู้คืน
- ถ้าข้อมูลบนชีตว่างเปล่าแต่บนเว็บมีข้อมูล ระบบจะ **ปฏิเสธการกู้** เพื่อกันข้อมูลหาย (ถ้าต้องการล้างข้อมูลจริง ๆ ให้ลบที่หน้าแอดมิน)
- แก้ข้อความในชีต `Applications` / `Members` ด้วยมือ **ไม่มีผล** กับเว็บ (ระบบอัปเดตแถวตามรหัสทุกครั้ง)

## ระบบจัดการแก๊ง (/gang)
ระบบบริหารแก๊งสำหรับสมาชิกที่สมัครและได้รับอนุมัติจากเว็บไซต์แล้วเท่านั้น — ไม่มีการเพิ่มชื่อสมาชิกเองในระบบแก๊ง สมาชิกใหม่จะเข้าระบบอัตโนมัติเมื่อใบสมัครถูกอนุมัติ

### ฟีเจอร์หลัก
- **Activity Report** — ส่งรายงานกิจกรรม 3 ประเภท: `เล่นร้าน (shop)`, `เล่นลูป (loop)`, `เล่นแอร์ดอป (airdrop)` พร้อมผล `ได้/ชนะ` หรือ `ไม่ได้/แพ้`
  - `shop` ที่ได้ร้าน **ต้องแนบหลักฐาน**, `shop` ที่ไม่ได้ร้านไม่ต้องแนบ, `loop` และ `airdrop` **ต้องแนบหลักฐานทุกครั้ง**
  - สถานะรายงาน: `รอตรวจสอบ` → `อนุมัติแล้ว` / `ปฏิเสธ` → `ดำเนินการเรียบร้อย`
  - ระบบให้คะแนนจากรายงาน **ครั้งเดียวเท่านั้น** (ผูกด้วย `reportId`) และกันส่งซ้ำด้วย `requestId` + ช่วงเวลา 60 วินาที
- **คะแนน** — Leader ตั้งค่าคะแนนเริ่มต้นแยกตามกิจกรรม/ผลลัพธ์ได้; Deputy/Leader เพิ่มหรือหักคะแนนได้ แต่ต้องระบุเหตุผลทุกครั้ง ระบบเก็บประวัติพร้อมผู้ทำรายการและเวลา
- **MY RECORD** — ดูประวัติคะแนน การลา การเตือน/ความประพฤติ และประวัติกิจกรรมของตัวเอง (สมาชิกทั่วไปเห็นได้เฉพาะของตัวเอง)
- **ระบบลา** — ส่งคำขอลาได้ พร้อมสถานะ `รออนุมัติ / อนุมัติแล้ว / ไม่อนุมัติ`, กันช่วงวันที่ทับซ้อน และเก็บประวัติผู้อนุมัติ
- **ความประพฤติ / การเตือน** — Deputy/Leader บันทึกคำเตือนหรือบันทึกทั่วไปพร้อมเหตุผล และลบรายการได้
- **Leaderboard** — จัดอันดับตามคะแนน พร้อมสถิติกิจกรรม จำนวนครั้งที่ผ่าน ชัยชนะ และอัตราผ่าน (กรองช่วงวันที่/ค้นชื่อได้)
- **Realtime** — อัปเดตหน้าจอทันทีผ่าน Server-Sent Events (`/api/gang/events`) โดยไม่ต้องรีเฟรช
- **Discord Webhook** — แจ้งเตือนรายงานใหม่/ผลตรวจ/คะแนน/การลา/ความประพฤติ/ตำแหน่ง/ตั้งค่า โดยเก็บ URL ฝั่ง Backend เท่านั้น หน้าแอดมินเห็นแค่ตัวอย่างที่ปิดบางส่วน
- **Audit Log** — บันทึกทุกการกระทำสำคัญ เช่น ตรวจรายงาน ปรับคะแนน เปลี่ยนตำแหน่ง อนุมัติลา และแก้ตั้งค่า

### ตำแหน่งและสิทธิ์
| ตำแหน่ง | เห็นข้อมูลทั้งแก๊ง | ตรวจรายงาน/ลา | ปรับคะแนน/เตือน | ตั้งค่า/เปลี่ยนตำแหน่ง | Audit |
| --- | :---: | :---: | :---: | :---: | :---: |
| Member | — | — | — | — | — |
| Staff | ✓ | ✓ | — | — | — |
| Deputy Leader | ✓ | ✓ | ✓ | — | ✓ |
| Leader | ✓ | ✓ | ✓ | ✓ | ✓ |

ค่าเริ่มต้นระบบจะแปลงตำแหน่งเดิมของเว็บให้อัตโนมัติ: `BOSS` → Leader, `LEADER` → Deputy Leader, `SUPPORT` → Staff, อื่น ๆ → Member และ Leader เปลี่ยนตำแหน่งผ่านหน้า `/gang` ได้ทันที (มีผลกับการล็อกอินครั้งถัดไป/เรียลไทม์)

### เข้าใช้งาน
- เปิด `/gang` แล้วเลือกแท็บ **สมาชิก** ใช้ **ชื่อ IC + รหัสผ่านบอร์ด** ชุดเดียวกับ `/board`
- หรือเลือกแท็บ **แอดมิน** ใช้ `ADMIN_USER` + `ADMIN_PASSWORD` ชุดเดียวกับ `/admin`
- เมนูเข้า `/gang` ถูกเพิ่มไว้ที่หน้าแรก, บอร์ดสมาชิก และหลังบ้านแล้ว
- สมาชิกที่ถูกให้ออกจากแก๊ง (`exitedAt`) จะถูกตัดสิทธิ์ทันที

### ตั้งค่า Discord / Google Sheets
- **ไม่ต้องตั้งค่าเพิ่ม** หากยังไม่ต้องการแจ้งเตือน — ระบบจะข้ามการส่ง Discord
- ตั้ง Discord Webhook ได้ที่ `/gang` → Admin → **ตั้งค่าระบบ** (เก็บใน `data/settings.json` ฝั่งเซิร์ฟเวอร์) หรือจะใช้ env `DISCORD_WEBHOOK_URL` เป็นค่าสำรองก็ได้ — ค่าที่ตั้งในหน้าเว็บจะถูกใช้ก่อน
- Google Sheets ใช้ตัวแปร `SHEETS_WEBHOOK_URL` / `SHEETS_SECRET` ชุดเดิม และต้อง **deploy Apps Script เวอร์ชันใหม่** ตามหัวข้อ "ส่งข้อมูลเข้า Google ชีต" เพื่อให้รองรับชีตใหม่ทั้ง 6 ตาราง + Leaderboard
- ระบบจะส่งเฉพาะข้อมูลธุรกรรม (Members, Activity Reports, Score History, Leave History, Behavior History, Leaderboard) — ตั้งค่าและ Audit Log **ไม่ถูกส่งขึ้นชีต**

### ไฟล์ข้อมูล
- `data/reports.json` — รายงานกิจกรรม
- `data/scores.json` — ประวัติคะแนน (แหล่งความจริงของคะแนนสะสม)
- `data/leaves.json` — คำขอลา
- `data/behavior.json` — ความประพฤติ/คำเตือน
- `data/audit.json` — Audit Log
- ทุกไฟล์ถูกสำรองอัตโนมัติผ่านระบบ `.seed.json` + GitHub backup เดียวกับข้อมูลสมาชิก

### หมายเหตุด้านความปลอดภัย
- ทุก API ของแก๊งตรวจสิทธิ์จากเซสชันจริง ไม่รับตำแหน่งจากฝั่ง Client
- สมาชิกทั่วไปดูได้เฉพาะรายงาน/คะแนน/การลา/ประวัติของตัวเอง
- Upload หลักฐานต้องล็อกอินก่อน และรับเฉพาะไฟล์รูปภาพขนาดไม่เกิน 4MB
- ไม่มีรหัสผ่านหรือ Webhook เต็มรูปแบบถูกส่งกลับไปฝั่ง Client
- หากใช้ Render ฟรี ควรตั้ง GitHub backup ให้ครบ เพราะดิสก์ถูกล้างทุกครั้งที่ deploy/restart

## เผยแพร่ผ่าน Render
> **สำคัญ:** `package.json` และ `server.js` ต้องอยู่ที่ราก (root) ของ repository — อัปโหลด "เนื้อในโฟลเดอร์" ไม่ใช่ทั้งโฟลเดอร์ ถ้าอัปโหลดซ้อนโฟลเดอร์ ให้ไปตั้ง Root Directory ใน Render Settings

โปรเจกต์นี้มี backend จึงไม่ใช่เว็บ static อย่างเดียว และไม่สามารถเอาไปวางบน Cloudflare Pages แบบ static ตรงๆ ได้
1. สร้าง repository ใหม่บน GitHub แล้วอัปโหลดไฟล์ทั้งหมดในโฟลเดอร์นี้ (ไม่ต้องอัปโหลด `node_modules`)
2. เข้า Render แล้วสร้าง **New Web Service** จาก repository
3. Build Command: `npm install`
4. Start Command: `npm start`
5. ใน Environment Variables ของ Render เพิ่ม:
   - `ADMIN_USER` = ชื่อผู้ใช้แอดมินที่ต้องการ
   - `ADMIN_PASSWORD` = รหัสผ่านที่เดายากและไม่ใช้ซ้ำกับบัญชีอื่น
   - `SESSION_SECRET` = สตริงสุ่มยาวๆ ที่ไม่เปิดเผย
   - `NODE_ENV` = `production`
   - `PUBLIC_URL` = ลิงก์เว็บจริง เช่น `https://twentyfive.onrender.com` (ใช้ในข้อความ DM)
   - `DISCORD_BOT_TOKEN` = โทเคนบอทดิสคอร์ด (ถ้าต้องการให้ระบบส่ง DM อัตโนมัติ — ไม่ใส่ก็ได้)
   - `DISCORD_GUILD_ID` = ไอดีเซิร์ฟเวอร์ดิสคอร์ด (ไม่บังคับ — ใส่แล้วบอทค้น User ID จากชื่อผู้ใช้ได้)
   - `DISCORD_WEBHOOK_URL` = Webhook สำหรับแจ้งเตือนระบบแก๊ง (ไม่บังคับ — ถ้าไม่ใส่ สามารถตั้งในหน้า `/gang` → Admin → ตั้งค่าระบบได้)
   - `BACKUP_KEY` + `BACKUP_GITHUB_TOKEN` + `BACKUP_REPO` = **แนะนำมากถ้าใช้ Render ฟรี** เพราะดิสก์ถูกล้างทุกครั้งที่ deploy/restart ดูวิธีตั้งค่าในหัวข้อ "ข้อมูลสำรองอัตโนมัติ"
   - `SHEETS_WEBHOOK_URL` + `SHEETS_SECRET` = ถ้าต้องการให้ส่งข้อมูลเข้า Google ชีตอัตโนมัติ (ไม่บังคับ) ดูหัวข้อ "ส่งข้อมูลเข้า Google ชีต"
6. Deploy แล้วเปิด URL ที่ Render ให้มา และเติม `/admin` สำหรับหลังบ้าน

## ข้อควรรู้ก่อนเปิดใช้จริง
- ข้อมูลสมาชิกถูกเก็บใน `data/members.json` และใบสมัครใน `data/applications.json` (มีไฟล์สำรอง `.seed.json` คู่กันเสมอ) บนโฮสต์ที่ดิสก์ถาวร (เครื่องตัวเอง/VPS) ใช้ได้ทันที ส่วน **Render ฟรีที่ดิสก์ถูกล้างทุกครั้งที่ deploy/restart ให้ตั้ง GitHub backup ให้ครบ** (`BACKUP_KEY` + `BACKUP_GITHUB_TOKEN` + `BACKUP_REPO`) ไม่งั้นข้อมูลจะหายทุกครั้งที่ deploy
- รหัสผ่านบอร์ดของสมาชิกถูกเก็บเป็นข้อความธรรมดาใน `data/members.json` เพราะแอดมินต้องกด "ส่งรหัสอีกครั้ง" ได้ ถ้าจะใช้งานจริงจังควรเปลี่ยนไปเก็บแบบ hash และใช้ระบบรีเซ็ตรหัสผ่าน
- หลังบ้านนี้มีระบบล็อกอินพื้นฐาน แต่ยังไม่มี rate limiting/ระบบรีเซ็ตรหัสผ่าน/ฐานข้อมูลถาวร ควรเพิ่มก่อนใช้กับข้อมูลสำคัญ (หน้า `/apply` มีการจำกัดจำนวนการส่งใบสมัครต่อ IP แล้ว)
- รูปภาพใส่เป็น URL ที่เข้าถึงได้สาธารณะเท่านั้น อย่าใส่ข้อมูลส่วนตัวที่ไม่ต้องการเผยแพร่
- ตั้ง `ADMIN_PASSWORD` และ `SESSION_SECRET` ให้แข็งแรง ห้ามใส่ความลับลง GitHub
